# Invoice Creation API: ID and Invoice Number Response & Lookup Design

- **Date**: 2026-09-07
- **Author**: Antigravity & Manuel
- **Status**: Approved

---

## 1. Problem Statement

Currently, the invoice creation API (`POST /api/v1/books/invoices`) in `ContaWeb.Api.Book.Invoice.create/2`:
1. Dispatches `Conta.Command.SetInvoice` via `Conta.Commanded.Application.dispatch/1`.
2. Responds with `json(conn, "ok")` (HTTP 200) upon success, without returning any identifier for the newly created invoice.
3. The invoice UUID (`id`) is only generated downstream in the read-model projector (`Conta.Projector.Book.Invoice`) when inserting into the Postgres table `book_invoices`. Neither the command `SetInvoice` nor the domain event `Conta.Event.InvoiceSet` carry an `id`.
4. If the client did not provide an `invoice_number`, the aggregate (`Conta.Aggregate.Company`) calculates the sequential integer correlative (e.g. `1`), but the API caller has no way of knowing what number was assigned without querying the read database.
5. In addition, `GET /api/v1/books/invoices/:id` calls `Conta.Book.get_invoice(id)` which does `Repo.get(Invoice, id)`. Because `book_invoices.id` is a `:binary_id`, attempting to query by invoice number (e.g. `"2026-00001"`) fails with an `Ecto.Query.CastError`.

---

## 2. Goals & Requirements

1. **Optional `id` in `SetInvoice`**: The command must accept an optional `:id` (`:binary_id`). If provided by the client, it is used; if not provided, the API controller generates one using `Ecto.UUID.generate()` before dispatching.
2. **Optional `id` in `InvoiceSet`**: The domain event must include `field :id, :binary_id` as optional. Existing events stored in EventStore that lack an `:id` must deserialize cleanly without breaking.
3. **Projector Backwards Compatibility**: In `Conta.Projector.Book`, if `event.id` is present, it is used as the primary key of `book_invoices`. If `event.id` is `nil` (such as during replay of historical events), a UUID is autogenerated.
4. **Commanded Execution Result**: The API controller will dispatch the command with `returning: :execution_result`. From the resulting `%Conta.Event.InvoiceSet{}` event, the controller extracts the assigned `invoice_number` integer, formats it via a standardized helper, and returns:
   - HTTP Status: `201 Created`
   - Body:
     ```json
     {
       "id": "c0a80101-0000-0000-0000-000000000001",
       "invoice_number": "2026-00001"
     }
     ```
5. **Dual Lookup in `Conta.Book.get_invoice/1`**: Adapt `get_invoice/1` and `get_invoice!/1` to test if the argument is a valid UUID via `Ecto.UUID.cast/1`. If valid UUID, look up by primary key `id`; otherwise, look up by `invoice_number`. This seamlessly enables querying `GET /api/v1/books/invoices/:id`, `/download`, and `/credit_note` by either UUID or formatted invoice number.

## 3. Detailed Architecture & Flow

### 3.1. Command & Event Schema Updates

#### `Conta.Command.SetInvoice`
- Add `field :id, :binary_id`.
- Add `:id` to `@optional_fields`.
- Changeset casts `:id` if present.

#### `Conta.Event.InvoiceSet`
- Add `field :id, :binary_id`.
- Add `:id` to `@optional_fields`.
- Changeset casts `:id` if present.
- When deserialized from historical JSON, missing `"id"` defaults to `nil`.

#### `Conta.Aggregate.Company`
- In `execute(%__MODULE__{} = company, %SetInvoice{} = command)`:
  - The aggregate passes through `command.id` into `InvoiceSet.changeset()`.

### 3.2. Projector Updates

#### `Conta.Projector.Book` & `Conta.Projector.Book.Invoice`
- In `Conta.Projector.Book.Invoice.changeset/2`:
  - Add `:id` to `@optional_fields`.
- In `Conta.Projector.Book` (`%InvoiceSet{action: :insert}`):
  - Ensure `id = invoice.id || Ecto.UUID.generate()`, and put `:id` in the attributes map passed to `Invoice.changeset/1`.

### 3.3. Formatting Helper: `Conta.Book.to_invoice_number/3`
Extract `to_invoice_number(date_or_year, number, is_credit_note \\ false)` from `Conta.Projector.Book` into `Conta.Book.to_invoice_number/3` (publicly accessible):
- Accepts:
  - `date`: `Date.t()`, ISO string, or integer year.
  - `number`: integer or string.
  - `is_credit_note`: boolean (default `false`).
- Returns formatted string:
  - Regular invoice: `"2026-00001"`
  - Credit note: `"CN-2026-00001"` (using configurable prefix).

### 3.4. Dual Lookup in `Conta.Book.get_invoice/1` & `get_invoice!/1`
```elixir
def get_invoice(id) when is_binary(id) do
  case Ecto.UUID.cast(id) do
    {:ok, uuid} -> Repo.get(Invoice, uuid)
    :error -> Repo.get_by(Invoice, invoice_number: id)
  end
end

def get_invoice(nil), do: nil

def get_invoice!(id) when is_binary(id) do
  case Ecto.UUID.cast(id) do
    {:ok, uuid} -> Repo.get!(Invoice, uuid)
    :error -> Repo.get_by!(Invoice, invoice_number: id)
  end
end
```

### 3.5. API Controller: `ContaWeb.Api.Book.Invoice.create/2`
- When `action == "insert"`:
  - Check `params["id"]` or `params[:id]`. If missing or empty, generate `id = Ecto.UUID.generate()` and set `params = Map.put(params, "id", id)`.
  - Validate with `SetInvoice.changeset(%SetInvoice{}, params)`.
  - Dispatch with `dispatch(command, returning: :execution_result)`.
  - On success:
    ```elixir
    {:ok, %Commanded.Commands.ExecutionResult{events: events}} ->
      invoice_set = Enum.find(events, &match?(%Conta.Event.InvoiceSet{}, &1))
      invoice_number = Conta.Book.to_invoice_number(
        invoice_set.invoice_date,
        invoice_set.invoice_number,
        invoice_set.is_credit_note
      )

      conn
      |> put_status(:created)
      |> json(%{
        "id" => invoice_set.id || command.id,
        "invoice_number" => invoice_number
      })
    ```
- When `action == "update"`:
  - Keep existing behavior (`json(conn, "ok")` or `%{"status" => "ok"}`).

## 4. Test Strategy

1. **Unit tests in `Conta.BookTest`**:
   - Verify `to_invoice_number/3` formats regular invoices and credit notes correctly.
   - Verify `get_invoice/1` and `get_invoice!/1` work with UUIDs and with formatted `invoice_number` strings.
2. **Aggregate tests in `Conta.Aggregate.CompanyTest`**:
   - Verify `SetInvoice` with an `id` emits `InvoiceSet` preserving that `id`.
   - Verify `SetInvoice` with `id: nil` emits `InvoiceSet` with `id: nil`.
3. **Projector tests in `Conta.Projector.BookTest`**:
   - Verify `InvoiceSet` with `id` projects `book_invoices` with that exact UUID.
   - Verify `InvoiceSet` with `id: nil` projects `book_invoices` with an autogenerated UUID.
4. **API Integration tests in `ContaWeb.Api.Book.InvoiceTest`**:
   - `POST /api/v1/books/invoices` without `id`:
     - Returns HTTP 201 Created.
     - Body contains `"id"` (valid UUID) and `"invoice_number"` (formatted, e.g. `"2026-00001"`).
   - `POST /api/v1/books/invoices` with explicit `id`:
     - Returns HTTP 201 Created with that exact `"id"`.
   - `GET /api/v1/books/invoices/:id`:
     - Can query using the returned `"id"` (UUID).
     - Can query using the returned `"invoice_number"`.
   - `GET /api/v1/books/invoices/:id/download`:
     - Can download PDF using either UUID or `invoice_number`.
